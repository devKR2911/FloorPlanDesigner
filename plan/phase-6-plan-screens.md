### Where the result differs from the plan

- **Network failures get a plain message.** When the backend cannot be reached at all, the browser's own wording is "Failed to fetch". The list, the editor and the dialogs now say "The server could not be reached. Check that it is running, then try again."
- **The unsaved-changes rule is its own small class,** `change-tracker.ts`, used by the `use-unsaved-changes` hook, so it could be tested without a browser.
- **A plan is loaded afresh on every visit to its editor.** A copy kept from an earlier visit is never shown in place of the saved plan.
- **The rename and delete dialogs share one file with the create dialog,** `PlanDialogs.tsx`, and `App.tsx` is gone: the router renders the screens.
- **The preview picture is sent on every save,** and Duplicate copies the original's picture, so a copy has one before it is ever opened.

## Goal

The app opens on a list of saved plans. From there a plan can be created, opened, renamed, duplicated and deleted. Opening one shows the editor at its own address, and the editor knows whether the plan has unsaved changes and warns before they are lost.

This replaces the temporary pieces from Phase 0: the lone Save button with a name field, the `?plan=<id>` address, and the "N saved plans" counter.

## Where things stand

- **Backend:** the routes this phase needs already exist: list, create, read, update (name, document or both) and delete. The list returns names and dates without the documents.
- **Web app:** `Editor` creates a plan on the first save and updates it after that. The plan id lives in a query parameter. There is no router and no way to see, rename or delete saved plans.
- **Backend tests** only cover request validation, with a database that throws if touched. Nothing tests the routes against a real database yet; that is Phase 7.

## Design

### Router

**TanStack Router** is added, to go with TanStack Query: route parameters are typed, and a route can wait for its plan to load before the editor mounts. Routes are written in code, in one file; three routes do not need the file-based plugin.

| Address          | Screen                                                                  |
| ---------------- | ----------------------------------------------------------------------- |
| `/`              | Plan list                                                               |
| `/plans/$planId` | Editor for one plan                                                     |
| anything else    | "Page not found", with a link to the list                               |
| `/?plan=<id>`    | Redirects to `/plans/<id>`, so addresses from earlier phases still work |

A plan that does not exist, or an id that is not valid, shows "This plan could not be found" with a link to the list.

### Creating a plan

"New plan" asks for a name in a small dialog, with "Untitled plan" filled in, creates the plan on the backend, and opens it. A plan therefore always has an id by the time the editor shows it, which removes today's "not saved yet" state and its special case in the save code.

### Plan list screen

- **Cards** in a grid, most recently changed first: a preview picture, the name, and when it was last changed ("2 hours ago", with the exact time on hover).
- **Per plan,** a menu with Open, Rename, Duplicate and Delete. Clicking the card opens the plan.
- **Rename** is a dialog with the name field. **Delete** asks for confirmation and names the plan. **Duplicate** makes "Copy of <name>" and stays on the list.
- **Filter:** a field above the grid narrows the list by name as you type. It appears once there are more than six plans.
- **States:** placeholders while loading; a message with a Retry button if the list cannot be loaded; and, with no plans, a short welcome with one "New plan" button.
- The list refreshes after every create, rename, duplicate and delete. A deleted plan disappears at once and comes back with a message if the delete fails.

### Preview pictures

A list of names alone is hard to scan, so each plan stores a small picture of itself.

- **Engine:** `engine.editor.snapshot({ width, height })` draws the plan fitted to a small off-screen canvas, with rooms, walls, openings and items but no grid, dimensions, corner handles or selection, and returns it as a PNG data URL. An empty plan returns `null`.
- **Saving:** the web app takes a 320 × 200 snapshot on each save and sends it with the document.
- **Backend:** the `plans` table gains a nullable `thumbnail` text column through a migration. The update and create requests accept an optional `thumbnail`: a PNG data URL of at most 100 kB. The list returns it. A plan with none shows a neutral placeholder.

### Editor screen

The header changes; the toolbar, the catalogue panel and the canvas stay as they are.

- **Back to the list:** a "Plans" link at the left.
- **Name:** shown as editable text. Changing it and pressing `Enter` or leaving the field renames the plan at once, on its own, without saving the drawing.
- **Save:** the button is enabled only when the drawing has unsaved changes, and `Ctrl+S` or `Cmd+S` does the same. The status beside it reads "Unsaved changes", "Saving…", "Saved" with the time, or the error if saving failed.
- **Unsaved changes** are tracked from the model's change events: any change after the plan was loaded or last saved.
- **Leaving with unsaved changes** (the Plans link, the browser's back button, closing the tab) asks first. Inside the app the dialog offers Save and leave, Leave without saving, and Stay. Closing the tab uses the browser's own prompt, which is all a page is allowed to show.
- **The tab title** is the plan's name.
- **A plan deleted elsewhere:** a save that gets "not found" says so and offers to go back to the list.

Saving stays a deliberate action in this phase, not automatic. There is no undo until Phase 7, and with autosave a wall deleted by mistake would be saved within seconds. Until then, reloading the page is the way back to the last save.

### Data layer

`features/plans/queries.ts` gains `useCreatePlan`, `useRenamePlan`, `useDeletePlan` and `useDuplicatePlan`, and `useSavePlan` becomes update-only. `lib/plan-url.ts` is removed; the router owns the address.

- **One package:** `@tanstack/react-router`.
- **Three shadcn components,** generated into the project by its CLI: `Dialog`, `AlertDialog` and `DropdownMenu`. They build on the `radix-ui` package the app already has.

## Steps

1. Backend and shared package: the `thumbnail` column and migration, the schemas, the routes; tests for the schemas and for request validation.
2. Engine: the plain drawing mode and `snapshot()`.
3. Router: the package, the three routes, the redirect from `?plan=<id>`, the not-found screens.
4. Data layer: create, rename, delete and duplicate; save becomes update-only; `plan-url.ts` removed.
5. Plan list screen: cards, menu, dialogs, filter, and the loading, error and empty states.
6. Editor screen: header, renaming, unsaved-changes tracking, Save and its shortcut, the leave prompts, the snapshot on save.
7. Browser check, then this file and the project plan are updated with the result.

Estimated size: 1,300 to 1,700 lines including about 250 of tests. One go-ahead covers all seven steps, the package and the three shadcn components.

## Not in this phase

- Autosave. It is the natural next step once undo exists (Phase 7).
- Detecting that a plan was changed in another tab or by someone else. The last save wins.
- Accounts and per-user plans (Phase 8). Every plan is visible to everyone who can reach the app.
- Folders, tags, sorting options, paging, and restoring deleted plans.
- Exporting or importing a plan as a file, and printing.
- Component tests for the web app with a simulated browser. The web app's test tooling for that is part of Phase 7.

## Open questions

The defaults below will be implemented unless you say otherwise.

1. **TanStack Router** as the router. React Router is the well-known alternative; it would work equally well here and is a like-for-like swap.
2. **Saving stays manual,** with unsaved-changes tracking and prompts, until undo exists.
3. **A new plan is created on the backend straight away,** after asking for a name, not on its first save. An abandoned new plan stays in the list as an empty plan until it is deleted.
4. **Preview pictures are stored with each plan.** Leaving them out saves the migration and about 250 lines, and the list would show names and dates only.
5. **Duplicate is included.** It is a small addition on top of create.
6. **Renaming in the editor saves at once,** separately from the drawing.

## Later changes

- **2026-11-12: the plan list picture is the 3D view, not the 2D drawing.** `engine.view3d.snapshot()` draws the plan the way the orbit view shows it (walls facing the camera lowered, no grid or selection) to a 320 × 200 JPEG at 2×, which works while the 3D view is hidden and leaves it as it was. The 2D `editor.snapshot()` remains as the fallback when the 3D picture cannot be drawn. Thumbnails may now be PNG or JPEG data URLs.
